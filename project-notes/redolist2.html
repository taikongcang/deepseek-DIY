现象：点"卸载"→ 弹窗停在「正在卸载…」永远不动，取消键灰色，只能关窗口。

项目内容
根因（实证）卸载要交给 pnpm；我们发完 pnpm remove <包> 后等它回话，等到才去更新"已装清单"并提示成功。但 pnpm 把活干完了却不肯退出进程（Windows 上的毛病）→ 我们永远等不到回话 → 请求永不返回 → 界面永久转圈。代码层：runPnpm() 只 await handle.done，全链路零超时。
连带后患（要紧）因为一直没回话，后续"更新清单"那步压根没执行 → 出现"包已从磁盘删掉、清单里还写着它"的中间态 → app 启动时照清单去找、找不到就报错 → 下次启动直接失败、进恢复助手。
改动 ①
给等待设上限		await handle.done → Promise.race([handle.done, expiry])；新增常量 PNPM_OPERATION_TIMEOUT_MS = 5 分钟（可由构造项 pnpmTimeoutMs 覆盖，已加入参数校验）。5 分钟无回话 → handle.cancel() 掐掉子进程 → 抛 operation-failed（消息含 did not finish within … ms）。
效果：界面再也不会永久转圈，最坏是等 5 分钟后弹一个明确报错。
改动 ②
不管成不成先对平账		executeUninstall：先捕获 pnpm 失败/超时、不立刻抛 → 重读 profile 的 package.json → 若发现"依赖已被删"（说明 pnpm 其实干完了活）→ 就顺手把 dsh.profile.bundles 里的该包也去掉 → 然后才抛原错误。
效果：从源头上不再产生"包没了但清单还写着"的脏状态。
