## 一、🔴 三条硬约束（决定"能不能改、能改多少"）

### 约束 1：**客户端单文件上限 262144 字节（256 KiB），而且 1.7.28 已经贴到边**

| | 字节 |
|---|---|
| 上限 | **262144** |
| **1.7.28 的 `lib/client.js`** | **261898** |
| **剩余余量** | **246 字节** |

来源：`scripts/build.mjs` 末尾强制校验 + `test/verify.mjs:122` 断言（**两处都卡**）。上游注释原文：
> 「DSH STORE 自动审核对固定 Commit 内**每个源码文件**设 256 KiB(262,144 字节)单文件上限，**片段与压缩产物双双受检**，任一超限即失败（不得靠跳过未读源码通过审核）」

⇒ **这意味着"往上加 UI"几乎不可能**。想加，就**必须先减**。

⚠️ **一处我不替你说死**：这条是**上游自设的构建门禁 + 插件商店审核口径**。我们是**本地安装**（`dsh plugin add <tgz>`），**严格来说未必受这条约束** —— 但**我没有实测过**放宽后的运行表现，所以不能保证。**要放宽必须实测。**

### 约束 2：**客户端源码被拆成 4 个"有序片段"**

```
src/client/
├── 01-open-styles-i18n.js            108832 字节（余 153312）
├── 02-validators-helpers-sidebar.js  182416 字节（余  79728）
├── 03-model-sidebar.js                 5711 字节（余 256433）
└── 03-settings-panels-main.js        169637 字节（余  92507）
```

- **文件名的排序顺序 = 程序顺序**（`01` → `02` → `03`）；构建时按序拼接再整体压缩。
- 上游注释解释原因：客户端是**单个 `__ModuleLoader__` 工厂闭包**，**不能拆成真正的 ES 模块**，只能用"有序片段"。
- 片段文件名必须匹配 `^\d{2}-[a-z0-9-]*\.js$`，否则构建直接报错。
- 注意：有两个 `03-` 开头（`03-model-sidebar.js` 排在 `03-settings-panels-main.js` 前）。
