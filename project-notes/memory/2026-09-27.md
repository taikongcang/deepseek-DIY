# 2026-09-27

## 用户提问：官方更新与官方桌面版是同一个东西吗？我们是不是只需要用官方桌面版了？

### 查证结果

**Q1：是一体的，但发布物分离。**

- 官方 README 原文（`apps/desktop/README.zh.md`「关键技术决策 · 发布身份」）：
  > 「Electron 与 `@deepseek-ai/dsh` **始终使用同一精确版本**。**即使桌面壳代码不变，升级 dsh 也必须发布新 Desktop 版本。**」
- ⇒ **桌面版没有独立版本号**：桌面版叫 `0.1.7-rc.2`，就是内核那个号（`test` 环境才追加 `.YYYYMMDD.index`）
- ⇒ 与实测吻合：GitHub 8 个 release **全部是 `dsh-v...` 内核 tag，没有一个 desktop tag**
- **但产物分离**：桌面安装包**不进 GitHub release**，走 `download.deepseek.com`（生产）/ `download-test.deepseek.com`（测试），固定 Nightly 通道（`nightly.yml` / `nightly-mac.yml`）

**Q2：不能"只用官方桌面版"。四条硬理由（都是 README 原文/实测）：**

1. **还没开放** —— 「已知限制」第一条原文：**「账号登录尚未接入；登录按钮禁用」**。主 README 对用户只宣传 Web。测试包走 `feishu-test` 登录鉴权（`allowedAuthOrigins`），正式包才是 `anonymous` ⇒ **仍是内部/受控发布**。
2. **拿不到正式安装包** —— 生产发布 = EV 证书签名 + 公证 + 上传腾讯 COS + CDN 回读验收，全是官方内部流程；GitHub 上无桌面产物。
3. **它不带我们的东西** —— 官方桌面版用**共享 Web 插件管理器**（`packages/boot/plugin-manager`），**没有第三方插件市场**；也没有我们的中文界面/`lisa`·`R9` 命名/`deepseekharness.diy`/便携模式/更新源。
4. ⭐ **它有自动更新，会覆盖自制** —— 启动后异步查固定 Nightly，用户点一下就下载安装并重启。**装官方桌面版 = 我们的改动会被官方版本盖掉**，与「一切皆自制」直接冲突。

**架构差异（换基座不是打补丁能完成的）：**

| | 官方桌面版 | 我们（社区版改的） |
|---|---|---|
| 形态 | **薄壳**：Electron 只加载打包的 Web 资源，Host 是私有 `apps/desktop-host` | Electron **即宿主**，Cordis 根跑在 Electron main 进程内 |
| profile | **独占 `$DSH_HOME/profiles/desktop`，CLI 不能启动或修改** | 我们自己的 profile 体系 |
| 运行时 | **自带 Python（numpy/pandas/python-docx/pptx/openpyxl/Pillow/lxml/XlsxWriter）+ Node + pnpm**；默认注册 `office-docx`/`office-pptx`/`office-xlsx` 技能 | 无内置 Python 运行时 |
| 包来源 | `app.asar/dsh` 携带完整生产依赖树，**profile 只装外部插件**；启动**从不运行 pnpm** | profile 里装包 |
| 恢复 | **原生恢复对话框**：退出 / 重启 / **禁用第三方插件** / **备份 profile patch 并重启** | 我们要做的 N10 |
| 签名 | Windows **EV 证书**（SafeNet Token + SignTool + DigiCert 时间戳）/ macOS Developer ID + 公证 | 无签名 ⇒ 被 SAC 拦（N12） |
| 端口 | 19387（Web 是 3080） | 同社区版 |

**值得学的三处（对我们有价值）：**
- 「**薄壳**」架构决策（2026-09-10 决策文档）：共享 Web 行为 + Desktop 适配分离
- **运行时解析 + 启动从不跑 pnpm**：消除用户机器上的核心包安装过程，顺带规避了 pnpm 卡死那类问题
- **原生恢复对话框的四选项**（尤其「备份 `cordis.patch.yml` 并重启」）—— 与我们 N10 的「分级 + 宽容 + 可见」思路一致，且它连「patch 备份」都想到了

**顺带印证两件我方待办：**
- **N7（profile 名 `desktop` 改名的必要性上升）**：官方也占用了 `profiles/desktop` 这个名字
- **N12**：官方 README 原文「未签名构建**可能被 Windows 代码完整性策略阻止；任何构建模式都不会关闭该策略**」= 官方承认，解法就是 EV 签名

### 结论（给用户的方向判断）

- **不一回事**：桌面版 = 内核 + Electron 壳，**同版本号、两个发布物**。
- **不能只用官方桌面版**：拿不到、未开放、不含我们的定制与市场、且**自动更新会覆盖自制**。
- **但它是最值得研究的参照**（比社区版 `dsh-desktop` 更权威）：官方把「桌面壳该怎么做」的答案都写在仓库里了 —— 薄壳、运行时解析、原生恢复、EV 签名。若将来要重做桌面壳，**它比社区版更适合当基座**。

## 对比：官方源码 vs 我们（I:\dsh-913，3.0.0）—— 用户问「有什么不同」

| 维度 | **官方**（0.1.7-rc.2） | **我们** |
|---|---|---|
| 包管理器 | **pnpm@11.7.0** | **yarn@4.18.0** |
| 组织 | monorepo：`apps/`(4) + `packages/`(**54 组**) + native/python/vendor/scripts | **3 个自有包**（desktop·fabric·market）+ `patches/`(**21**) + `vendor/`(**266 tgz**) |
| 桌面壳 | `apps/desktop/src` = **61 文件 / 7,090 行** | `dsh-plugin-desktop/src` = **173 文件 / 33,412 行** |
| 后台 Host | ⭐ **独立进程** `apps/desktop-host`（6 文件 / 342 行） | **未拆分**（跑在 Electron main 内） |
| **内核来源** | ⭐ **本仓源码** `packages/*` | ⭐ **`vendor/` 266 个官方 tgz** |
| **改内核方式** | ⭐ **直接改源码** | ⭐ **打补丁（21 个）** |
| 版本号 | `0.1.7-rc.2`（与内核同号，规则写死） | `3.0.0`（自有序列） |
| 插件市场 | **无市场**（只有 plugin-manager 管理器 + UI） | ✅ **`dsh-community-market`（40 文件 / 10,468 行，自写）** |
| 运行时 | 自带 **Python + Node + pnpm** + Office 技能 | 无 |
| 签名/更新 | **EV 证书 + 自动更新** | 无签名（SAC 拦，N12）/ 自有更新源 |

**⭐ 一眼可判的最本质分界**：
- 官方 `apps/desktop/package.json` 的 `dependencies` **只有 5 个**（`electron-updater`·`semver`·`ws`·`@deepseek-ai/dsh-api-gateway`(workspace:*)·`@deepseek-ai/cordis`(workspace:~)）—— **内核是同一仓库源码，靠 workspace 引用**
- 我们 `dsh-plugin-desktop/package.json` 的 `dependencies` = **一长串 `@deepseek-ai/dsh-*@0.1.5-rc.1` 精确版本**（来自 vendor tgz）

⇒ **「能直接改」与「只能打补丁」的根本分界就在这**。**要彻底落实 §〇「一切皆自制」（改内核而不打补丁），以官方源码为底座是唯一路径。**

**我们额外有**：插件市场 · 21 补丁（中文化/目录选择器/pnpm 升级/侧栏双列）· `lisa`·`R9`·`deepseekharness.diy` 命名 · 便携模式 · 自有更新源。
**官方额外有**：54 组内核源码 · 独立 Host · 自带运行时与 Office 技能 · EV 签名与自动更新 · 0.1.6/0.1.7 新功能。
