### ⚠️ 我没能证实的部分（如实说明，不编）

**"为什么前 19 天不拦、今天开始拦"的精确机制，我没有权威依据。**
与证据**一致**的最可能解释（**属推断，非实证**）：SAC 原先处于"关闭/非强制"态（注册表 `SAC_PreviousState = 0` 支持这一点），**今天 Defender 平台更新触发了信任模式重评估 → 转为强制**；官方 FAQ 也写明「**近期的 Windows 更新允许启用/重新启用智能应用控制，且不需全新安装**」。
注意：**拦截（20:57:51）发生在 20:58 那批配置变更之前**，所以"策略刷新导致拦截"这个因果方向**站不住** —— 刷新更像是同步发生的后果。

### 官方规则（查 microsoft.com 支持文档 + SAC FAQ）

1. 「**目前沒有辦法繞過單一應用程式的智慧應用程式控制保護**」→ **SAC 没有白名单/放行单个 exe 的机制**；Defender 的排除项对它**无效**。
2. 只有两条路：**关掉 SAC**，或**让开发者用"有效签名"签名**（= 受信任根计划里的 CA 签发；**自签名不算**）。
3. **关闭 SAC 后通常无法再开回来**（需重置/重装）；但官方又说"近期更新允许重新启用、无需全新安装"—— **这条我未在本机验证，标为「待验证」**。
4. SAC 靠"**预测模型信任 且/或 有有效签名**"放行；被判"无法可靠预测"的未签名程序会被拦。
5. 三种模式：评估（不拦）/ 开（拦）/ 关；**离开评估态后，除非重装/重置否则回不去**。

### 🔴 一条严重警告（写进档案，防止以后有人乱试）

**严禁手动改注册表 `VerifiedAndReputablePolicyState` 去"关掉" SAC。** Microsoft Learn 问答里有用户把它改成 0 再重启，结果 **SAC 反而开始拦几乎所有程序（PowerShell、regedit、Chrome、VS Code 全被拦）**，官方给的补救只有「重置此电脑（保留文件）」。**这条路不能走。**

### 给用户的结论（一句话）

**不是我们改坏了，也不是软件损坏** —— 是 Windows 的 SAC 今天开始"强制执行"，而我们自打包的 exe **没有代码签名**，所以被拦。**SAC 没有"放行单个应用"的功能**，只有"关掉 SAC"或"买证书签名"两条路。
