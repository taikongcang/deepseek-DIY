# 2026-09-28

## 用户提问：把官方源码按「之前改 desktop 的老方法」改成我们自己的，可行吗？

### 结论：**可行 —— 但准确说不是"照搬"，是"两层照搬 + 一层必须换"**

| 层 | 我们以前对社区版的做法 | 套到官方源码 | 判定 |
|---|---|---|---|
| **改自有源码** | 直接改 `dsh-plugin-desktop/src/**` | 官方 `apps/desktop/src`、`apps/desktop-host`、`packages/**` **就是源码** | ✅ **完全一样** |
| **改内核** | **打补丁**（21 个 `patches/*.patch`） | 内核在仓库内 ⇒ **直接改源码** | ✅ **升级**（不再需要内核补丁） |
| **构建链** | `yarn@4.18.0` + `yarn dist:win`（electron-builder） | **`pnpm@11.7.0`** + 自研脚本 `tsx scripts/package-target.ts win-x64` | ❌ **必须整个换掉** |

### ⭐ 补丁会大幅减少，但**不会归零**

- **不再需要的**：所有 `@deepseek-ai/dsh-*@0.1.5-rc.1.patch`（中文化 / 侧栏双列 / 目录选择器 / 设置 / 会话持久化 / web-app / presets …）—— 它们在官方源码里就是 `packages/**` 的源码，**直接改**。
- **仍然需要的（第三方包，不在官方仓库里）**：
  `pnpm@11.27.0.patch`（N1 治本）· `fs-ext` · `open` · `vscode-ripgrep` · `app-builder-lib`
  ⇒ **补丁数：21 → 约 5 个**，且剩下这几个是"外部依赖"性质，与内核无关。

### 硬门槛（实测数据，决定能不能落地）

| 项 | 官方要求 | 我们现状 |
|---|---|---|
| Node | `^22.19.0 \|\| >=24.0.0` | ✅ 有 22.22.2 / 24.19.0 |
| 包管理器 | **pnpm@11.7.0**（corepack；根 workspaces 6 组 glob：`vendor/*` `packages/*/*` `native/system` `native/system/packages/*` `apps/*` `website`） | ❌ 现用 yarn，**要换** |
| 依赖安装 | `pnpm install`（54 组 packages + 全部依赖，下载量大） | 未跑过 |
| **原生模块** | `native/system` —— **仓库里没有预编译 `.node`**；`build:native-system` = `tsx native/system/scripts/build.ts --host-addon-only`；`native/system/packages/` 只有 `darwin-*` / `linux-*` / `entry` ⇒ **Windows 需本地编译** | ⚠️ 未验证 |
| **Windows 打包** | README 原文：**「要求设置 `DSH_DESKTOP_APP_ID` 并具备常规构建依赖，包括编译原生模块所需的 Python 和 Visual C++ 构建工具」**；且「Windows 打包使用 **Visual C++ Build Tools 和 Windows SDK** 编译 x86 Win32/GDI+ 辅助库」 | ❌ 需装工具链 |
| 签名 | `package:win:x64:unsigned` 可免 EV；正式签名需 EV 证书 | ❌ 我们无证书（N12） |

### 收益 / 代价

**收益**
1. **补丁 21 → ~5**：内核改动全部变成直改源码（**这才是 §〇「一切皆自制」要的形态**）
2. **不再需要 `vendor/` 里 266 个 tgz**（内核在仓库内）
3. 直接拿到官方 0.1.7 全部功能（插件管理页 / 原生恢复 / 侧栏终端·Office·浏览器·diff）

**代价 / 风险**
1. **构建环境重**：pnpm + Python + Visual C++ Build Tools + Windows SDK（本机是否具备**未验证**）
2. **每次官方发版要 merge**：我们改了源码，官方 0.1.7→0.1.8 时要用 git 合并解决冲突（比补丁好维护，但仍是持续成本）
3. **我们的东西要重做**：插件市场（10,468 行）· 命名 · 便携模式 · 自有更新源
4. **必须改掉自动更新**（否则连 `download.deepseek.com` 被官方版覆盖）
5. **路径必须先挪**：现在在含中文路径下，构建会踩坑 #1

### 未实测的两项（如实标注）
- `pnpm install` 能否在本机跑通
- Windows 打包工具链是否齐备（Python / VS Build Tools / Windows SDK）

### 未改任何产品代码。
