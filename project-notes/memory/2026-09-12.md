## 用户问 "pinned deepseek-harness" 是什么（已讲解）
- **pin = 钉住版本**；官方中文译法「**固定版本的上游子模块**」（CONTRIBUTING.md:37）。
- **三层锁定**：①`.gitmodules` 锁仓库地址 `deepseek-ai/deepseek-harness.git` ②`upstream.json` 锁 commit `cd5ef8148158c3a752a658978873241fdf8e2bbc` + sourceVersion `0.1.2-alpha.1` ③`vendor/.../manifest.json` 锁构建产物（241 包 + sha256）。
- **专门文档**（必读）：`.agents/notes/implemented/process/2026-08-15-pinned-upstream-and-isolated-yarn-workspace.zh.md`，含 Problem / Decision / Verification / 5 个被否决方案 / Consequences。
- **关键澄清（解释了为何 submodule 是空的）**：原话「普通桌面构建从 npm registry 解析已发布的 DSH 包，**不从子模块链接源码**」→ 平时根本不需要 submodule，它只是"可审查的精确源码参照" + 追更新时的编译源。
- **规矩**：submodule 视为**只读**（桌面分支一行不许改）；更新上游要在**独立提交**里同时改 gitlink 与元数据（pin 更新与桌面功能改动必须分开提交）；`yarn check:layout` 会拒绝变化的子模块 URL/提交/工作树/包管理边界。
- **代价（文档自认）**：克隆必须 init 子模块；贡献者需维护**两套包管理器缓存**（外层 Yarn + 上游 pnpm）；GitHub 公开源码版本与 npm 发布 family 可能不对应，故"源码 pin 更新"与"运行时 family 更新"要分别给验证证据。
- **被否决的 5 个备选**：根目录携带可编辑上游文件 / subtree 或复制快照 / 加入 Yarn workspace 或源码链接 / 把上游转成 Yarn / 把 npm 运行时版本当作对应源码修订的证明。

## 桌面版网络架构查实（回答用户"本机 HTTP/WebSocket 仅限本机"）
源码 `dsh-plugin-desktop/src/desktop-network.ts`（全文 87 行）关键事实：
- `type DesktopNetworkExposure = 'loopback' | 'lan'`，默认值 `'loopback'`（`index.ts:139/171` z.union 默认 loopback）。
- **`desktopWebServerHost()` 无条件 return `'127.0.0.1'`**，注释原话："The upstream HTTP origin is **never exposed**; LAN intent controls only the HTTPS edge." → **官方 Web 服务器（HTTP）永远只听本机，任何情况下都不对外**。
- 局域网访问 = 桌面版自己另起一层 **HTTPS/WSS 边缘**：`desktopLanBrowserUrls(port, addresses)` → `https://<LAN-IPv4>:port/`；`DESKTOP_LAN_HTTPS_AVAILABLE = true`。
- **浏览器访问只有 compatibility 模式才允许**：`desktopBrowserAccessAvailable(mode) => mode === 'compatibility'`；`desktopNetworkExposureForBrowserAccess(false, x) => 'loopback'`。
- 界面进程来源：`index.ts:263` `rendererOrigin = http://127.0.0.1:${ctx.webServer.port}`；`desktop-settings-route.ts:39/44` 校验请求来源必须是 `127.0.0.1` 或 `::1`，否则拒绝。
- → **这解释了待办②「局域网访问开关置灰」**：LAN HTTPS 只在兼容模式 + 浏览器访问启用时才有意义；高级模式下该开关必然不可用（因为 advanced 不允许普通浏览器访问）。
