## 新发现：`.pnpm-store` 跑到盘符根 E:\

- 现象：`E:\.pnpm-store\v11\`（files + projects），仅 56K，创建于首启装依赖时（00:02）。
- 根因（查源码钉死）：pnpm 是通过 `pnpm.ts` 的 `start()` spawn，其 `env` 是**精简替换版**（只传 PATH/NODE/ELECTRON_RUN_AS_NODE/DSH_HOME/CI/npm_config_* 共 7 个，无 USERPROFILE/HOME/HOMEDRIVE/APPDATA）；pnpm 算 store 路径时 `os.homedir()` 拿不到有效 home，回退到 cwd（activeProfileDir）所在盘符根 E:\。
  - 注意：`clear-env.mjs`（`desktop-runtime-environment.ts` 的 `clearEnvironmentModule()`）只删 `ELECTRON_RUN_AS_NODE` 一个变量，不是它清空的 home。
- 性质：pnpm 内容寻址缓存，非数据，删了可重建，当前近乎空。
- 待办候选：若要让 store 也跟随 data，可在 pnpm.ts `start()` 的 env 里加 `npm_config_store_dir`（指向 data 下），需改代码 + 重打包，未定，等用户拍板。

## DevTools 界面语言改中文不生效（06:52 排查）

- 用户诉求：托盘/菜单"切换开发者工具"弹出的 DevTools 窗口，在其 Settings→Preferences→Language 里选中文**不生效**。
- 排查事实（实测）：
  - 安装目录 `E:\app\deepseekharness\locales\zh-CN.pak` **存在**（中文语言包在，排除"打包精简掉中文包"）。
  - Electron **43.3.0**（很新，Chromium 较新，DevTools 有 Language 设置）。
  - 系统语言 **zh-CN**（LocaleName=zh-CN，Languages=zh-Hans-CN）。
  - `main.ts` 无 `--lang`/`app.setLocale`/`app.commandLine.appendSwitch('lang')` 干预；`electron-runtime.ts` 的 `setLocalePreference()` 只做 `rebuildTrayMenu`+`rebuildApplicationMenu`，**不碰 Chromium UI locale**。
- 根因判断（基于 Electron 机制 + 官方文档）：DevTools 的界面语言走的是 **Chromium UI locale**（由启动参数 `--lang` 决定，Electron 官方支持 `--lang`="Set a custom locale"），**不跟随** dsh 应用自身的"切中文"（那是应用层 i18n，两套独立），DevTools 设置里的 Language 下拉是 Chrome 浏览器机制、Electron 里常不生效；未设 `--lang` 时走 en-US fallback。
- 验证法（不需重打包）：完全退出（含托盘）后命令行 `"E:\app\deepseekharness\deepseekharness.exe" --lang=zh-CN` 启动，看 DevTools 是否变中文。
- 永久改法（需重打包）：`main.ts` 在 `app.whenReady()` 之前加 `app.commandLine.appendSwitch('lang', 'zh-CN')`。**尚未实施**，等用户决定是否为一个调试窗口的小事重打包。
