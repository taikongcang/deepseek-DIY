## 22:30–22:50 对照实验：PyInstaller 打包 vs SAC 拦截

**用户原话**：「"安装一个 pyinstaller，然后使用 `pyinstaller --onefile --windowed --name="QMT自动交易" gui_app_integrated.py` 这个命令就可以打包了" —— 看看这个打包方法是什么，这种打包方法好像就不会被windows阻拦。」

- **SAC 仍是强制模式**（`VerifiedAndReputablePolicyState = 1`）—— **用户没关**，与 09-21 报障时一致 ⇒ 可以做对照。

### 实验与结果（4 组，全部通过）

| # | 做什么 | 结果 |
|---|---|---|
| 1 | **严格按用户给的命令**打 `QMT自动交易.exe`（7,429,044 字节） | ✅ 能运行（报 `No module named 'tkinter'` → **证明 PyInstaller 引导器已解包并执行了 Python 代码**）；**零拦截事件** |
| 2 | `--add-data` 塞 200 MB 随机数据 → 产物 **207 MB**（对齐我们被拦那个的 215 MB） | ✅ 能运行；**零拦截** ⇒ **体积不是原因** |
| 3 | 纯控制台包（不依赖 tkinter），看完整输出与退出码 | ✅ `STAGE-1/2/3` 全打印、**EXIT=0** ⇒ **决定性证据** |

**签名对照**：PyInstaller 产物 = **`NotSigned`**（**它不做签名**），连它自带的引导壳 `runw.exe` 也是未签名 —— 与我们的 `deepseekharness.exe` **完全一样**。

### ⚠️ 实验 5 失败（如实记录）
从命令行启动我们自己的 `deepseekharness.exe`（22:38:58）：**无拦截事件**，**但 `data\desktop\logs\` 也没有任何新日志** ⇒ **它根本没真正跑起来** ⇒ **该对照无效**，"启动方式（双击 vs 命令行）是否影响判定"**无结论**。

### 结论
- ✅ **用户的说法在我这次实测里成立**：未签名的 PyInstaller 产物在本机 SAC 强制模式下**能正常运行**（3 个构建 × 4 种场景，全通过）。
- ⚠️ **机制完全不清楚** —— 为什么 Electron exe 被拦、PyInstaller 产物不被拦，**查不到权威解释**；可猜方向（云信誉模型对文件结构判定不同）**未证实，不编**。样本量小，**不代表所有机器/版本**。
- 🔴 **最关键：这个方法解决不了 N12** —— **PyInstaller 只能打包 Python 程序**（把 Python 解释器 + .py + 依赖塞进自解压 exe）；**deepseekharness 是 Electron/Node 应用 ⇒ 用不了**。它**只对用户那个 Python 项目（QMT 自动交易）适用**。
