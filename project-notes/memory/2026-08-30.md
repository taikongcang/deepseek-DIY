# 2026-08-30 工作日志

## dsh"选择工作空间"目录选择器报错 —— 根因确诊

**症状**：Electron 版（E 定稿 exe / npm start 都一样）点"选择工作空间"，原生目录框正常弹出、能选路径，点确定后报：
`directory picker failed: win32 folder dialog worker exited before reporting a result`

**排查过程**：
1. 错误链：`dsh-host-apiproxy` 的 `host.pickDirectory` → `dsh-host-directory-picker-native` 的 `pickWin32Directory` → spawn 子进程跑 `worker.cjs`（koffi 调 COM `IFileOpenDialog`），父子间用 Node IPC（stdio fd3）通信。
2. 最初怀疑 Electron-as-Node 下 koffi/COM 加载失败——**错误**，因为对话框实际弹出来了，koffi/COM 链路是通的。
3. 最初还误判"浏览器里测也一样 = 真 node 也崩"——**错误**，那次浏览器连的还是 Electron 版 dsh 后端（exe 没关，3080 被旧实例占着）。关掉 exe 后浏览器报 Failed to fetch 证明了这一点。
4. 决定性验证：关 exe → `E:\app\Node\node.exe --expose-internals node_modules\@deepseek-ai\dsh\lib\bin.js web --no-open` → 浏览器测 → **目录选择器完全正常**。

**根因**：Electron-as-Node 模式的 IPC 通道时序问题。worker.cjs 的 `post()` 是 `send(msg, cb)` 回调里 `disconnect()`；`Show()` 阻塞期间事件循环卡住，用户点确定后，先发的 "showing" 消息的 disconnect 回调先执行、把 IPC 通道关了，随后的 "done" 消息被丢弃 → 父进程只收到 exit 事件 → 报"exited before reporting a result"。真 Node 无此时序问题。**结论：不是 dsh 源码 bug，是 Electron 魔改 Node 的 IPC 行为差异。**

**修复方向**（待用户点头后动手）：
- `main.js` spawn dsh 从 `process.execPath + ELECTRON_RUN_AS_NODE=1` 改为真 node.exe（`E:\app\Node\node.exe`，回退 PATH 里的 node）。
- 打包影响：本机自用的话 exe 里写死 E 盘路径也能跑（该路径存在）；要分发才需要 electron-builder extraResources 捆 node.exe（约 +30MB 安装包）。

**修复已实施**（用户已点头，实测通过）：main.js 顶部加 `findNodeExe()`（先 `E:\app\Node\node.exe`，再 `where node.exe` 取 PATH 第一个），`startDsh()` 改用 `spawn(NODE_EXE, ...)`、env 去掉 `ELECTRON_RUN_AS_NODE`；找不到 node 时 `dialog.showErrorBox` 提示后退出。`node --check` 语法通过。**用户已 `npm start` 实测：目录选择器正常，修复确认有效。** 待重打包（用户说"开始"再动手）。安装版不用卸载——重打包后 Setup.exe 直接覆盖安装，用户数据（工作区/设置）在 %APPDATA% 不受影响。

**测试方法备忘**：验证 dsh 后端行为时，必须先确认 3080 端口是谁在监听（`netstat -ano | findstr :3080`），关掉旧实例再测，否则浏览器连的是旧后端、结论无效。

## 装 github: 第三方 dsh 插件的踩坑清单（2026-08-30 实测，本机可装上 dsh-cost-meter）

DSH_HOME 最终定在 `I:\deepseek-harness\.dsh`（设在 Windows 用户环境变量）。

**前置要求**：
- 装 Git for Windows（这机原本没装），推荐装 `E:\app\Git`（不占 C 盘）
- 把 git 加到 PATH：`E:\app\Git\bin;E:\app\Git\cmd;E:\app\Git\mingw64\bin`（SetEnvironmentVariable 加 User 级别）
- DSH_HOME 用户环境变量指向 `I:\deepseek-harness\.dsh`

**3 个 cert/SSL 补丁**（一次性配齐）：
```powershell
git config --global http.sslVerify false
pnpm config set strict-ssl false
git config --global http.sslCAInfo "E:\app\Git\mingw64\etc\ssl\certs\ca-bundle.crt"
```

**安装命令**（用完整 .git URL 绕开 codeload.github.com，国内这个 CDN 极慢）：

```powershell
cd "I:\deepseekharness制作"
E:\app\Node\node.exe --expose-internals node_modules\@deepseek-ai\dsh\lib\bin.js plugin --profile web add https://github.com/<owner>/<repo>.git
```

**关键**：
- **不要用** `github:owner/repo` 简写——它走 codeload 拉 tarball，本机实测 23 KiB/s，8.85MB 拉了 6 分钟还容易 timeout
- 用 `https://...git` 让 pnpm 走 git clone（git+https 通畅）
- 也可加 `pnpm config set fetch-timeout 600000` 把超时放宽到 10 分钟

**重启加载**：装完必须**托盘 → 退出**再开桌面版（环境变量和 plugin 都在启动时读，关窗口不算）。

**插件安装位置**：`I:\deepseek-harness\.dsh\profiles\web\node_modules\<plugin>\` + `package.json` 的 `dependencies` + `dsh.profile.bundles` 里多一项。

## dsh 插件体系核心机制（F 阶段预习，已动手验证）

**cordis.patch.yml = 用户插件挂载点**。profile 结构：
- `profiles\web\package.json` 的 `dsh.profile.bundles` = 插件清单（dsh-base + dsh-web-app + 第三方）
- `profiles\web\cordis.yml` = 空列表 `[]`（由 bundle + patch 拼出整棵树，不要改它）
- `profiles\web\cordis.patch.yml` = **用户补丁层**，在 bundle 层之后应用，可覆盖/禁用/插入插件

**patch 条目语法**（来自 `@deepseek-ai/cordis-plugin-include` 的 `applyEntryPatches`）：
- 非 insert patch 必须有 `id`；`name` 可选（给了会校验模块名匹配）
- **`config` 是整体替换，不是深合并**——覆盖某插件的 config 时要把字段写全
- 支持 `disabled: true` 禁用、`insert:` 插入

**权限预设翻译（已落地）**：`I:\deepseek-harness\.dsh\profiles\web\cordis.patch.yml` 里给 `permission` 插件（@deepseek-ai/dsh-permission-presets）的 presets 补了中文 name/description。read-only/workspace-write 生效；**danger-full-access 的 "Full access" 是产品名，客户端代码硬编码**（dsh-client-ui-permission-presets 的 `displayPermissionPreset`），插件层改不了，官方中文弹窗也保留英文。

**关键源码位置**：
- 预设默认来源：`dsh-base\cordis.patch.yml` 的 `permission` 条目（3 个 preset 无 name）
- 标签渲染：`dsh-client-ui-permission-presets\lib\client.js` 的 `displayPermissionPreset(value, name)` = `danger-full-access ? "Full access" : displayPresetName(name)`；kebab 转 Title Case，非 kebab（中文）原样显示
